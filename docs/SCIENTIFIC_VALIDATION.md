# Scientific validation summary (the single citable page)

This is the one-page-per-experiment summary a reviewer should read
before citing DockFlow-Automator.  Everything below is computed from -
and regenerable from - the committed artifacts under `benchmarks/`; the
headline claims are stated with their confidence intervals and their
definitions.  The full per-number regeneration procedure is Section 7.

**Scope statement (read first):** DockFlow-Automator is a BETA
automation layer around established docking tools (Vina, Meeko, RDKit,
OpenBabel).  This page evaluates WHAT THE PIPELINE DOES on public
benchmarks; it makes **no claim of superior performance** relative to
any other tool, and it does not validate cross-docking, flexible
receptors, covalent docking, or multi-seed variability (Section 6).

## 1. Redocking benchmark (24 complexes)

Protocol: each complex's co-crystallized ligand is re-docked into its
own prepared receptor; receptor preparation engine `auto` (resolved to
OpenBabel in the published run), grid box from the co-crystallized
ligand + 4.0 Å padding (strong assumption on every complex), Vina
python bindings 1.2.7, exhaustiveness 8, num_modes 9, seed 2026,
2 threads.  Complex set: `benchmarks/redocking/complexes.csv`
(24 PDB ids with ligand, UniProt, resolution, SHA-256 of the committed
raw PDB - drift-detectable).

Headline numbers (all definitions published to prevent
definition-shopping; formal definition in
`docs/interaction_criteria.md#pose-recovery-the-formal-definition`):

| pose-recovery definition | ≤ 1.0 Å | ≤ 2.0 Å | ≤ 3.0 Å |
|---|---|---|---|
| rank-1 (formal: best-scoring pose) | 15 | **21** | 22 |
| top-3 (best RMSD among 3 best-scored) | 20 | **23** | 23 |
| best-any-rank (v0.3.x legacy) | 20 | **23** | 23 |

* rank-1 pose recovery: **21/24 = 87.5% (95% Wilson CI 69.0–95.7%)**
* best-any-rank: **23/24 = 95.8% (95% Wilson CI 79.8–99.3%)**
* best-pose RMSD distribution: min 0.02 / p25 0.26 / median 0.62 /
  p75 0.86 / max 3.03 Å (mean 0.67, std 0.62; n = 24)
* per-target grouping (best-any-rank): HIV-1 protease 5/6; other
  targets 18/18
* failure modes (the point of publishing multiple definitions):
  1DWD and 1HPV recover a ≤ 2.0 Å pose at rank 3 - **ranking**
  failures (Vina scoring), not sampling failures; 1HTG (the only
  best-any-rank failure, a 17-rotatable-bond peptidomimetic) has no
  pose within 3.0 Å at any rank - a **sampling** failure.  Every
  failed complex had a strong ligand-derived grid box, so failures are
  docking-side, not preparation-side (per-complex preparation + grid
  provenance in `redocking_results.csv`).
* artefacts: `benchmarks/redocking/results/` (per-complex run dirs
  incl. poses, summary with all sub-tables, histogram
  `rmsd_distribution.png`, top-N curve `topn_success.png`, scatter).

**Correction notice:** the v0.3.x numbers (18/24, mean 1.32 Å) were
computed with an atom-order-dependent symmetry RMSD that over-penalised
symmetric ligands by up to ~0.5 Å; the corrected implementation (see
Section 4) reproduces the independent reference exactly and was applied
to re-analyse the same bit-identical poses.  See CHANGELOG 1.0.0rc1.

## 2. MGLTools 1.5.7 comparison (21-complex subset)

Protocol: identical Vina (python bindings, same box, seed 2026,
exhaustiveness 8); the ONLY difference is preparation chemistry -
DockFlow (OpenBabel receptor + Meeko ligand) vs
`prepare_receptor4.py`/`prepare_ligand4.py` (MGLTools 1.5.7, bioconda
build with bundled Python 2.7).

**Denominator (explicit):** success rates are computed on the
21-complex MGLTools-completed subset - 3 genuine MGLTools crashes are
excluded (full tracebacks in
`benchmarks/mgltools_comparison/results/failures/`, crash stage +
one-line root cause in the CSV).  This is NOT a head-to-head
24-vs-24 comparison.

* pose recovery (best-any-rank, 2.0 Å): **DockFlow 20/21 = 95.2%
  (95% CI 77.3–99.2%) vs MGLTools 18/21 = 85.7% (95% CI 65.4–95.0%)**
* mean best-pose RMSD delta (MGL - DF): +0.25 Å; mean affinity delta:
  -0.087 kcal/mol
* receptor heavy-atom counts: identical on every MGL-completed complex;
  ligand heavy atoms and polar hydrogens identical; rotatable-bond
  perception differs on 6/21 (macrocycles + single-bond disagreements)
* preparation-property aggregate over all 24 complexes (incl. the
  crashes, marked): `docs/preparation_validation.md`
  #cross-workflow-24-complex, generated by
  `benchmarks/preparation_validation_aggregate.py`
* upstream-faithfulness check: meeko's own CLI on the same input
  produces identical preparation properties (same atom counts, torsions,
  charge statistics) to DockFlow's wrapper

## 3. DUD-E enrichment (3 targets, 133 ligands each)

Protocol (identical for all targets): seeded subsample (40 actives +
93 decoys, `random.Random(2026).sample` over the committed
SHA-256-pinned ISM lists), Meeko ligand prep (input protonation, no
tautomers), DockFlow receptor prep from the reference PDB, box from
the co-crystal ligand + 4.0 Å, Vina exhaustiveness 1, num_modes 1,
seed 2026.

| target | receptor (PDB) | n actives | n decoys | ROC AUC | EF@1% | EF@5% | BEDROC (α=20) |
|---|---|---|---|---|---|---|---|
| hivpr | 1HVR | 40 | 93 | 0.665 | 3.325 | 2.375 | 0.6647 |
| aa2ar | 3EML | 40 | 93 | 0.593 | 1.663 | 1.900 | 0.5486 |
| parp1 | 2RD6 | 40 | 93 | 0.729 | 3.325 | 1.425 | 0.5157 |

This is an **evaluation** of the DockFlow+Vina pipeline, NOT a claim of
superior virtual-screening performance: single seeded run per target,
exhaustiveness 1, no comparative baseline against other tools on the
same panel, and the BEDROC random baseline (which depends on the
actives fraction) is measured explicitly over 10 000 seeded
permutations per target rather than assumed to be 0.5.
**Limitation:** three targets is a small panel; a publication-grade VS
benchmark would use the full DUD-E (102 targets) - future work, see
`ROADMAP_POST_V1.md`.

## 4. Symmetry-aware RMSD: independent validation

The crystal RMSD used everywhere above (RDKit `GetBestRMS` over
molecular-graph automorphisms, heavy atoms, superposed, atom-order
independent) is checked two independent ways:

1. **Analytic known-answer cases** (always on in CI):
   `tests/test_analyzer.py::test_symmetry_rmsd_known_cases` - benzene
   rotated 60°, naphthalene flipped 180°, aspirin carboxylate oxygens
   relabeled, a chiral no-automorphism ligand, and a genuinely
   1.5 Å-different pose (both methods must agree).
2. **Independent implementation cross-check** on every pose of the
   benchmark: `benchmarks/redocking/rmsd_crosscheck.py` compares
   DockFlow's RMSD against **spyrmsd's `symmrmsd`** (BSD-2, separate
   code base; benchmark-only tool, not a package dependency) on **193
   poses across all 24 complexes: max |Δ| = 0.0 Å** (scatter:
   `results/rmsd_crosscheck.png`).  This cross-check is what FOUND the
   v0.3.x atom-order bias (over-penalisation of reordered symmetric
   ligands); after the fix the two implementations agree to machine
   precision.  A hand-rolled Kabsch + automorphism fallback keeps the
   check runnable without spyrmsd.

## 5. Preparation validation

`docs/preparation_validation.md` compares, from committed artifacts:

* the three DockFlow receptor engines on 1HVR (atom counts, charges,
  AD4 typing; the `none` engine is scientifically degraded - zero
  charges, no aromaticity);
* DockFlow vs MGLTools on 1HVR and the 24-complex aggregate
  (identical heavy-atom geometry; torsion perception and ionised-group
  charges differ, quantified);
* meeko's own CLI vs DockFlow's wrapper (identical output properties -
  the wrapper adds provenance, not chemistry).

## 6. Known limitations (validation-specific)

* **Single seed** (2026) for every benchmark; multi-seed variability is
  not measured.
* **Exhaustiveness 8** (benchmark) / **1** (enrichment): higher
  exhaustiveness would change the sampling-failure boundary.
* **No cross-docking benchmark** (docking a ligand into a DIFFERENT
  structure of its target) - the 1HSG config exists as an example, but
  no cross-docking success rate is published.
* **No flexible-receptor benchmark**: side-chain flexibility
  (flexible residues) is implemented but not benchmarked; flexible-
  receptor scores are flagged incomparable with rigid-receptor scores.
* **No covalent-docking benchmark** (implemented, not benchmarked).
* **Redocking uses the deposited protonation** (template hydrogens at
  pH 7.4 nominal, NOT a pKa calculation) - see
  `docs/preparation_assumptions.md`; the report warns when catalytic
  residues line the box.
* Enrichment: 3 of 102 DUD-E targets, exhaustiveness 1, single seed.
* Vina's search is thread-count dependent; the published numbers were
  produced with 2 threads and the regeneration harness pins them
  (Section 7).

## 7. How to regenerate every number

Every published number is regenerable from the committed scripts +
datasets (no network needed beyond RCSB/DUD-E re-download checks):

```bash
# dataset pinning check (SHA-256 of the 24 committed PDBs)
python benchmarks/redocking/regenerate.py --skip-docking

# full benchmark regeneration + match assertion (re-docks all 24,
# pins cpu=2 to match the published thread count, asserts every
# numeric column within 1e-6, then re-runs the spyrmsd cross-check)
python benchmarks/redocking/regenerate.py --with-crosscheck

# re-derive the top-level summary/figures from the committed
# per-complex artifacts (no docking)
python benchmarks/redocking/run_benchmark.py --report-only

# MGLTools comparison (needs MGLTools 1.5.7; see its README)
python benchmarks/mgltools_comparison/compare_workflow.py \
    --mgltools /path/to/mgltools
python benchmarks/mgltools_comparison/compare_workflow.py --report-only

# enrichment: exact-panel reproduction with metric assertion
python benchmarks/enrichment/run_enrichment.py --reproduce

# preparation-property aggregate + meeko faithfulness
python benchmarks/preparation_validation_aggregate.py

# paper figures (from committed CSVs only)
python paper/figures/generate_figures.py
```

CI guards: the nightly workflow re-runs the regeneration and asserts
the match (`nightly.yml`); the doc-claim lint
(`tests/test_final_pass.py`) fails if a flagged claim word appears
unqualified; the analytic RMSD cases run on every push.
